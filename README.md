# Nexium Wallet v9 — Liquid Glass, боевой режим
Кастодиальный кошелёк в Telegram: пополнение и вывод через **Crypto Pay (@CryptoBot)**, переводы, обмен, P2P, чеки, запросы платежа, оповещения, поддержка, роли персонала, политика конфиденциальности и условия.

## Запуск
1. Vercel: подключить Upstash Redis. Env: `BOT_TOKEN`, `ADMIN_ID`, `APP_URL`, `WEBHOOK_SECRET`.
2. Crypto Pay: @CryptoBot → Crypto Pay → Create App → скопировать токен → env `CRYPTOPAY_TOKEN`. Webhook в настройках приложения: `https://ПРОЕКТ.vercel.app/api/pay`. Сначала проверь всё в тестнете (`CRYPTOPAY_TESTNET=1`, @CryptoTestnetBot).
3. Реквизиты для документов: `OPERATOR_NAME` (имя/название оператора), `CONTACT_USERNAME` (без @), при необходимости `LEGAL_DATE`.
4. Если бывший Toncoin в Crypto Pay называется иначе, задай `GRAM_ASSET` (по умолчанию `TON`).
5. **`LIVE_MODE=1` — боевой режим.** При первом входе пользователя все его старые виртуальные балансы и история обнуляются (иначе из тестовых «монет» можно было бы вывести реальные деньги). Без `LIVE_MODE` приложение работает в учебном режиме и честно помечено как таковое.
6. Deploy → один раз открой `/api/setup?key=WEBHOOK_SECRET` (вебхук, команды, описание). Документы: `/privacy`, `/terms`.
7. Пополни баланс приложения Crypto Pay (оттуда идут выплаты) и проверь Staff → Выводы → «Платёжеспособность».

## Как это работает
- **Пополнение:** приложение создаёт счёт Crypto Pay, пользователь платит в @CryptoBot, зачисление по вебхуку; также «Проверить оплату» и cron. Зачисление идемпотентно, сумма и актив сверяются с ответом API, а не с телом вебхука.
- **Вывод:** списание с баланса → выплата `transfer` на аккаунт @CryptoBot пользователя (`spend_id` защищает от дублей). До `wdAutoMax` USD (по умолчанию 50) — автоматически, выше — ручная проверка в Staff → Выводы. Определённый отказ платёжного сервиса — автоматический возврат монет; сбой сети или нехватка средств проекта — заявка уходит на проверку.
- **Защиты боевого режима:** выдача монет без обеспечения и сброс счетов отключены, минимум/дневной лимит/комиссия вывода настраиваются, экран согласия с документами обязателен, действия персонала в аудите.
- Роли: владелец, администратор, модератор, поддержка, кодер, тестировщик (вкладка Staff). Выводы и платёжеспособность видят владелец и администратор.
